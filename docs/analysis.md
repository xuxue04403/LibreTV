# 上游分析与改造决策

本文记录对 [LibreSpark/LibreTV](https://github.com/LibreSpark/LibreTV)（快照版本 2.19.7）的代码分析，以及为什么把它改造成「客户端直连」形态。

## 1. 上游是什么

一个 Next.js 15（App Router）+ TypeScript + Tailwind 的影视聚合站：

- **数据来源**：用户自行添加的 Apple CMS 采集站（`?ac=videolist&wd=` 接口）。
- **播放内核**：ArtPlayer + hls.js，带广告分片过滤、自动连播、倍速。
- **直播**：M3U 订阅 + XMLTV 节目单，HLS / HTTP-FLV 播放。
- **鉴权**：`PASSWORD` 环境变量 + HMAC 签名会话 cookie。
- **部署**：Docker / Vercel，必须 HTTPS（生产 cookie 带 `Secure`）。

代码规模（`src/`，不含测试）：

| 目录 | 文件数 | 说明 |
| --- | --- | --- |
| `src/app/api/**` | 18 | 全部服务端能力：搜索/详情/代理/直播/推荐/订阅/鉴权 |
| `src/app/**`（页面） | 5 | 首页、搜索、观看、直播、关于 |
| `src/components/**` | 26 | 播放器外壳、源管理、详情弹层、直播列表等 |
| `src/lib/**` | 45 | 解析、聚合、缓存、播放器工具、IndexedDB、SSRF |

## 2. 服务端到底承担了什么

这是决定改造方向的关键。逐个端点看：

| 端点 | 实际职责 | 是否必须服务端 |
| --- | --- | --- |
| `/api/search` | 并行请求多个采集站、分页、相关性过滤、健康度、NDJSON 流式返回 | ❌ 纯逻辑 |
| `/api/detail` | `?ac=videolist&ids=` 取详情；失败时爬详情页 HTML 提取 m3u8 | ❌ 纯逻辑 |
| `/api/proxy` | 图片/资源反代：补 UA/Referer 绕防盗链、绕 CORS | ⚠️ 浏览器必须，原生客户端不需要 |
| `/api/live/playlist` | 拉 M3U、解析频道/分组、导出 | ❌ 纯逻辑 |
| `/api/live/epg` | 拉 XMLTV、解 gzip、时间窗裁剪、6h 缓存 | ❌ 纯逻辑 |
| `/api/live/probe` | 批量测活（分片级探测、耗时、码率估算） | ❌ 纯逻辑 |
| `/api/live/stream` | 直播长连接转发（HLS/FLV） | ⚠️ 同 proxy |
| `/api/quality` | 解析 master playlist 推断分辨率 | ❌ 纯逻辑 |
| `/api/source/test` | 点播源探活 | ❌ 纯逻辑 |
| `/api/source-list` | 订阅拉取（服务端拉取，天然无 CORS） | ❌ 纯逻辑 |
| `/api/publish` | 上传源列表到 paste.rs 换短链 | ❌ 可直连 |
| `/api/douban`、`/api/bangumi/calendar`、`/api/hot-list` | 首页推荐，服务端直连 + 缓存 | ❌ 纯逻辑 |
| `/api/auth` | 密码校验、HMAC 会话、IP 限流 | ✅ 但本地客户端不需要 |
| `/api/status` | 版本号 + `DEFAULT_*` 下发 | ❌ 客户端改本地配置 |
| `/api/search` 里的 SSRF 校验 | 防止用户填的地址打内网 | ✅ 但客户端没有服务端攻击面 |

**结论**：服务端不是业务后端，而是一层「抓取 + 反代 + 鉴权」中间层。对本机客户端来说：

- 鉴权没有意义（没有多用户、没有公网入口）；
- SSRF 防护没有意义（客户端本就在用户自己的网络里）；
- 反代只在**浏览器内核**里必需（CORS / Referer），原生 HTTP 客户端不需要。

## 3. 改造方案与取舍

### 3.1 逻辑下沉：`packages/core`

把 `cms-parser`、`m3u-parser`、`m3u8` 广告过滤、聚合搜索、详情兜底、订阅解析等**纯函数**抽成共享包，HTTP 用接口注入：

```ts
interface HttpClient {
  request(url, options): Promise<HttpResponse>;
}
```

桌面端注入「主进程 IPC + 回环代理」，TV 端用 Kotlin 按同一语义重写（Kotlin 侧有 11 项对应的 JVM 单测）。

保留的语义细节（都是上游踩过的坑）：

- 采集站返回 `list: null` 视为空结果，而非错误；
- 分集优先取含 `.m3u8` 的线路（部分源第一条线路是网页中转页）；
- 详情接口无播放地址时，爬 `/index.php/vod/detail/id/{id}.html` 兜底；
- 相关性过滤：忽略标点/大小写、多词 AND、季数严格匹配（避免「第 2 季」误匹配 12 集）；
- 成人内容关键词过滤默认开启，可在设置关闭。

### 3.2 桌面端为什么还要一个本地代理

Chromium 渲染层受 CORS 约束：hls.js 拉跨域分片会被拦、`<img>` 加载豆瓣图会 403（防盗链）、`<video>` 播直链可能因缺 Referer 失败。

因此桌面端在主进程起一个**只监听 `127.0.0.1`、随机端口 + 随机 token** 的极简代理：

- 自动补 `User-Agent` / `Referer`；
- 把 m3u8 播放列表里的分片地址改写成代理地址（递归处理 `#EXT-X-KEY`、`#EXT-X-MAP` 的 `URI`）；
- 可按设置调用 `stripAdGroups` 过滤广告分片；
- 透传 `Range`，支持 MP4 拖动；
- 拒绝内网/回环/链路本地目标（可用 `LTV_ALLOW_PRIVATE_MEDIA=1` 放行自建源）。

它不是「部署服务端」：不监听外网、不带业务逻辑、随窗口退出。

### 3.3 Android TV 不需要代理

OkHttp 与 ExoPlayer 没有同源策略，直连即可；`NanoHTTPD` 之类的内嵌服务器纯属多余。代价是 HLS 广告过滤暂时无法在 Media3 里低成本实现（需要自定义 `HlsPlaylistParser` / 数据源改写），列为路线图。

### 3.4 直连带来的代价（明确记录）

| 上游做法 | 本项目做法 | 代价 |
| --- | --- | --- |
| 服务端统一抓取 | 客户端直连 | 采集站能看到用户真实 IP |
| 服务端缓存 | 客户端内存/短时缓存 | 多设备不共享缓存 |
| 服务端鉴权 | 无 | 无（单机应用不需要） |
| 服务端代理 | 桌面端回环代理 / TV 直连 | 桌面端多一个进程内组件 |

这些取舍对「个人本机播放器」场景是可接受的，但不应把本项目当作公网服务端使用。

## 4. 上游值得保留的设计

移植时特意保留了这些上游经验（多数来自真实故障）：

1. **源超时分级**：单源 10s 总死线，到点中断在途分页并在 UI 标「超时」，而不是等所有源串行超时；
2. **广告过滤的三层启发式**：URL 特征（`adjump`）→ 长正片夹超短段 → 片头短段，且「多分组封装不误删」的判据（片头组大小与其余组中位数同构则跳过）；
3. **季数匹配规则**：查询侧允许「庆余年2」，标题侧必须「第 2 季」或空格分隔，避免把片名里的数字当年份/季数；
4. **详情页兜底**：列表接口拿不到播放地址是常态，不是异常；
5. **订阅格式宽容**：共享 TVBOX 配置常带 `//` 注释、尾随逗号，需要先清洗再解析，否则一半订阅直接失败；
6. **NDJSON 流式返回**：搜索/测活/画质探测都边算边推，用户不必等最慢的源。

## 5. 未移植的能力

| 能力 | 原因 |
| --- | --- |
| 服务端密码鉴权 | 本地客户端无服务端 |
| SSRF 校验（服务端侧） | 无服务端攻击面 |
| 豆瓣/Bangumi 首页推荐 | 依赖服务端直连与缓存，TV/桌面首屏改为「继续观看 + 收藏」 |
| 画质探测与换源测速 | 可复用 core 增加，暂列路线图 |
| 离线下载 | 涉及分片解密与合流，暂列路线图 |
| 服务端磁盘缓存 | 单机场景收益有限 |
