# 双端全面测试与审计（2026-11-03，1.3.5）

用户要求（原文）：

> 对双端程序进行全面测试和审计，确保无bug无操作逻辑错误或不便！

上一轮（`docs/audit-2026-10-29.md`）是读代码找缺陷。这一轮换了方式：**四个并行子代理按"用户操作路径"逐条走查** + 两端实机跑 + 全量回归，重点找"看起来能跑但用起来别扭"的交互缺陷。

## 0. 复核方式

| 线 | 覆盖 |
|---|---|
| 子代理 A（TV 交互层） | 首页 / 分类 / 详情 / 搜索 / 设置 / 投屏 / 顶栏的焦点与可达性 |
| 子代理 B（TV 播放与生命周期） | 播放页与直播页的按键、看门狗、失败转移、前后台切换、DLNA 接收 |
| 子代理 C（桌面渲染层） | 播放页 / 详情面板 / 设置 / 直播页的键盘、弹层、状态竞态 |
| 子代理 D（主进程与 core） | 媒体代理、IPC、DLNA、`packages/core` 的边界与资源上限 |
| 实机 | AVD `tv35`（debug + release）+ 打包后的桌面 exe |

刻意排除的假阳性（子代理提了但不成立，已核对）：

- `DetailPanel` 没传 `timeoutMs`：core 自己有 10s 默认值。
- `DetailPanel` 立即播放可连点：按钮已按 `disabled` 挡。
- 首页用 `fav.id` 反查 history：与 `historyId()` 同格式，能对上。
- `Watch.tsx` 的 `triedRef.delete`：故意给"手动换源"一次新机会。
- 分类页 `onPartial` 提前 `setLoading(false)`：条件实际不可达。

## 1. 结论

**共 55 条：已修 39 条，部分修复 1 条（MAIN-03），未修 15 条**（都在 §5，逐条说明为什么不修）。

最高优先的三条，性质都是"用户会直接撞上、且看不出原因"：

1. **桌面：看完一集后进度被覆盖**（DUI-01）。`onEnded` 写完"看完 → 下一集"，播放 effect 的 cleanup 又用旧集号 + 片尾位置写一遍同一条记录。结果首页进度条恒 100%，点"继续观看"从刚看完那集的开头重放。
2. **TV：按 Home 键后仍在出声**（TVPB-01/02）。点播页只在 `isPlaying === true` 时暂停（缓冲中 `isPlaying` 是 `false`），直播页干脆没有生命周期处理。
3. **TV：DLNA 投屏控制条完全失效**（TVPB-03）。`Stop/Pause/Play/Seek` 四个动作是空实现，`GetTransportInfo` 恒回 `PLAYING`，`GetPositionInfo` 恒回 `00:00:00`。

## 4. 低危（已修 12 条）

- TVPB-12/13/14/16/17：媒体键不唤控件、`downHeld` 漏 KeyUp 永久失效、信息条按首次计时消失、`saveProgressNow` 空实现（删）、末集"下一集"无反馈。
- CORE-01：`http.stream` 无总量上限（`maxBytes` 默认 64MB，超限先 `reader.cancel()` 再抛）。
- CORE-02：流式中断兜底返回缺 `epgUrl`（节目单会突然整片变空）。
- PRELOAD-01：`streamId` 缺省时 chunk 全被静默丢掉（主进程新增 `http:stream:started` 先告知分配到的 id）。
- MAIN-03（**部分**）：SSDP 解析设备描述的条数与并发加了两道上限（32 / 6），但 `LOCATION` 主机仍只校验"与回包同网段"，未逐条校验解析出的主机地址。

## 5. 未修（15 条）与理由

| 编号 | 问题 | 为什么不修 |

| TVPB-11 | 最后一集看完记成"最后一集 0:00"，完成态丢失 | 要跨端给 `HistoryEntry` 加 `finished` 字段（core + 两端 + 迁移），属于模型改动，本轮先记为已知限制 |
